# V3 data dictionary and clock domains

Existing V2 tables are retained: conversations, messages, attachments, chunks, cases, predictions. Idempotent V3 migration adds v3_sources, v3_evidence, v3_runs, v3_cases, v3_reports and v3_annotations; schema_version gains 3 without rewriting old rows. New chat metadata labels manually_entered/model_generated; old rows are not retroactively altered.

Source types: real_uploaded, nasa_simulation, sire_synthetic_scenario, manually_entered, model_generated. These identify origin, not authenticity. Parsed or generated observations are not automatically verified physical measurements.

Canonical SourceRecord: content SHA-256, sanitized name, MIME, size, actual received UTC, parser version, privacy, authenticity, opaque storage locator and optional explicit asset/scenario. EvidenceRecord: source ID/type, exact pointer/excerpt or numerical snapshot, unit, observation time, information-availability time, quality, extraction method, human-verification flag and content hash. IDs are content-addressed EV:/SRC: tokens. SQLite triggers forbid source/evidence UPDATE/DELETE; case revisions/annotations are separate records. GET evidence validates the snapshot hash. V3 private originals remain under state/imports; audit retention is explicit and there is no automatic deletion interface for these originals.

Synthetic observations.sqlite3 contains only scenarios/assets/edges/telemetry/events. Evaluator truth is physically separate in evaluator_truth.sqlite3, with no API/retriever path. Observations opens read-only and uses an SQLite authorizer to deny other tables, writes and ATTACH. SQL is internal and parameterized. Scenario names are neutral trial IDs; fault labels are not public metadata. Generator source defines toy mechanisms but investigator receives no scenario truth assignments.

Telemetry key: scenario_id, asset_id, channel, observed_at. Values carry available_at, value (nullable), unit, quality and source_type. Hourly sampling, 96-hour observation horizon; late entries can become available through hour 100. Units include mm/s RMS, degC, bar, m3/h, rpm, A, %, L/min and boolean. Missing values stay null and are excluded from numerical summaries. Events unify work orders, maintenance, alarms and notes using event_type; each retains observation and availability clocks. Edges record explicit direction/type and validity dates. No inferred physical topology.

Simulation observation/availability timestamps are a labeled virtual clock beginning 2026-11-12 UTC. Actual source ingestion, run/report creation and human annotations use real UTC wall clock. Historical queries must filter both virtual source clocks; prior case memory also checks actual case creation availability. Late human review never changes an earlier measured snapshot.

Analysis uses first 24 visible samples versus latest six, with minimum-valid-count checks, not full-series normalization. Raw chart pagination does not alter analytical source windows. Default thresholds and budgets are in config/simulation.yaml. These are illustrative rules, not calibrated alarm limits. Generic JSON/office ingestion retains source data; automatic industrial sensor/units remapping and full uploaded-asset temporal analysis remain partial. C-MAPSS keeps its exact separate 26-column schema and training-domain policies.
