B. ORIGINAL ROOT CAUSES
1. Native files and scientific dependencies were excluded from the clone. They were restored before this repair; this task verified their actual bytes again.
2. /predictions/upload allowed only CSV. Its shared CSV path had a 10,000-row whole-file limit and validated the whole input as one engine. Original NASA TXT and normal multi-engine files therefore could not use the prediction UI.
3. Chat attachment forms did not send a NASA subset/compatibility declaration. The registered prediction tool accepted demo asset_id only, and free-text routing required an explicit FD subset plus demo engine. Uploaded predictions could not reach that tool.
4. Model readiness copied an older verification JSON even when local weights/dependencies were absent. There were no current file checks in that response.
5. Auto-executed predictions were not retained as an assistant prediction_id for automatic conversation-local follow-up lookup. UI handoff required an explicit selected saved result.
6. Conceptual/project-model questions lacked a dedicated current registry/data context. The global system prompt was not changed by this repair.
